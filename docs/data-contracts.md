# Built data contracts (data/build/*.json)

All files are compact JSON. Every hand-transcribed number is a **Figure** `{"value": number, "source": {"doc": str, "page": int|null, "url": str}}`. Money fields end in `_m` and are **millions of dollars**. Fiscal years are 4-digit ints; JSON object keys for years are strings ("2023"). The site fetches `../data/build/<name>.json` relative to `site/index.html` (serve the repo root).

- **headline.json** `{fy, total_budget_m, general_fund_m, enterprise_m, special_revenue_m, internal_service_m, capital_project_m, cip_m, gf_fte, gf_fte_change}` — all Figures except `fy`. FY2027: 6486.9 / 2256.7 / 1915.1 / 1207.9 / 225.7 / 23.5 / 858.1 / 8127.74 / −133.66.
- **funnel.json** `{fy, bar3: {pension_adc_m, debt_service_m, everything_else_m}, bar4: [{dept, amount_m}×9], gap_m}` — Figures. bar3: 396.3 (adopted GF Retirement ADC, FY2027 Adopted Budget Vol. I Citywide Budget Overview Table 8, p.30) / 75.0 / 1785.4. bar4 depts in order: Police 718.3, Fire-Rescue 402.3, Parks & Recreation 195.8, Library 74.3, Transportation 133.8, Homelessness Strategies & Solutions 62.0, Stormwater 68.3, Citywide Program Expenditures 214.8, All other 387.1 (sums to 2256.7). gap_m 118.0.
- **structural_deficit.json** `{convention: str, years: [16 × {fy, reported: bool, structural_deficit_m: Figure|null, one_time_resources_m: Figure|null, one_time_expenditures_m: Figure|null, suspended_reserve_m: Figure|null, includes_suspended_reserve: bool, resources_include_reserve: bool (true where one_time_resources_m already contains suspended_reserve_m: FY2012, FY2025, FY2026), components: [{label, amount_m}]|null, basis: str, note: str, gf_expenditure_adopted_m: number|null}], markers: [{fy, label, source: {source: Source} | Figure} | {fy, label, figures: [Figure, Figure]}, ×4]}`. FY2012–FY2027. `reported:false` for FY2015, 2016, 2017, 2021. `basis` is one of three strings: "proposed budget; gross one-time resources" (FY2012–21), "adopted budget; net of one-time expenditures" (FY2022–26), and a longer FY2027 string beginning "proposed budget; net of one-time expenditures". `gf_expenditure_adopted_m` is from the CSV (null for FY2027). Values are positive = size of gap. FY2022–FY2027 `structural_deficit_m` is the IBA's "Revised Structural Deficit (excluding reserves)" row (96.7 / 38.3 / 99.5 / 181.4 / 48.0 / 11.2, IBA 26-11 p.78) and `suspended_reserve_m` the "Suspended General Fund Reserve Contributions" row (10.7 / 24.3 / 0 / 22.4 / 55.6 / 80.1). FY2012's 35.1 already includes its 14.1 suspended reserve (`includes_suspended_reserve: true`).
  - **Build invariants** (`pipeline/build.py` `build_structural_deficit`, each tested): years unique and exactly FY2012–FY2027; `reported` and `resources_include_reserve` are booleans; `reported:true` ⇒ `structural_deficit_m` non-null; `reported:false` ⇒ every `_m` field null and `components` null.
  - **Markers** live in code, `pipeline/build.py` `DEFICIT_MARKERS` (not in curated JSON): fy 2011 "2010: temporary sales tax measure fails", 2025 "2024: sales tax measure fails" (IBA 26-11 p.77, which gives no month), 2026 "Trash fee adopted with FY2026 budget" (p.3), 2028 "FY2028 outlook: city $9.5M, IBA $32.9M" (no `source`; `figures` holds two Figures: 9.5 from FY2027 Adopted Budget Vol. I Citywide Budget Overview Table 10, p.36, and 32.9 from IBA Report 26-15 p.43, excluding reserve deposits).
  - **Chapter 1 derivation** (site, `deficit-bars.js` `prepare`): each reported bar has `solid_m` (the figure without the skipped reserve deposit), `reserve_m` (the deposit, 0 if none) and `top_m = solid_m + reserve_m`. Where `includes_suspended_reserve` is true (FY2012) the figure is split, `solid_m = value − reserve` (21.0 + 14.1); otherwise the reserve is stacked on top (FY2022–27 tops: 107.4 / 62.6 / 99.5 / 203.8 / 103.6 / 91.3, matching the IBA's "including reserves" row). `top_figure` is a derived Figure citing that row. Stats (`max_m`, `peak_share`, `mean_m`) stay on the IBA figure; the y-scale uses `max_top_m`.
- **flows.json** `{fy, nodes: [32 × {id, label, column: 0|1|2, kind: "utility"|"restricted"|"discretionary"|"borrowed"}], links: [30 × {source: id, target: id, amount_m: number, rule: str, ref: {doc, page, url}, highlight: bool}]}`. `kind` is validated at build time. Four column-1 rule nodes: `rule_utility`, `rule_restricted`, `gf_decides`, `rule_capital` ("Borrowed money: capital projects the Council picks", kind `borrowed`, fed by column-0 `bonds` "Bonds (borrowed for capital projects)"). Bond Financing in the FY2025 adopted CIP pays `bike_ped` 6.5 and `roads` 79.497; `rule_restricted` pays `bike_ped` 0.273 (TransNet) and `roads` 18.588 (TransNet 16.118 + trench-cut fees 2.47). Exactly one link has `highlight: true` (`rule_capital → bike_ped`, 6.5). Column-1 nodes balance within 1.0. No pension node (pension is inside department amounts). The site draws `borrowed` in the `--locked` colour with striped ribbons and its own key entry. Non-GF amounts are regenerated by `docs/research/flows_nongf.py`, which hard-codes FY2026 (operating) and FY2025 (CIP).
- **cuts.json** `{fy, reductions: [11 × {item, dept, fund, amount_m: Figure|null, reason: str, source: Source, reason_source: Source}], restorations: [7 × {item, status: str, amount_m: Figure|null, source: Source}]}`. Two reductions have `amount_m: null` (reason says why). Reduction amounts are the proposed-budget figures from the IBA's review (the site's column reads "Amount proposed"); some were later partly added back. Each restoration's `status` ("May Revision (...)", "IBA-recommended Council modification", ...) is shown per row, and its text before " (" is the source link's label.
- **gap.json** all Figures: `pre_cut_m` 118.0, `post_cut_city_m` 23.1, `post_cut_with_reserve_m` 103.2 (our arithmetic: 23.1+80.1), `skipped_reserve_m` 80.1, `population` 1419531, `households` 549999, `sales_tax_1pct_m` 386.7, `cuttable_m` 1785.4 (injected from funnel.bar3.everything_else_m).
- **claims.json** `[5 × {id, claim, finding, caveat, chart, sources: [Source], matched_projects: [str]|null}]`. ids in order: `bike-lanes`, `pensions`, `managers`, `trash-fee`, `homelessness`. `chart` is null for pensions, managers, trash-fee. bike-lanes chart: `{type: "grouped_bar", fy: 2025, groups: [{label, series: [{label, amount_m}]}×2]}` (one series has amount 0.0 — render as zero, do not omit). homelessness chart: `{type: "line", points: [{fy, amount_m, share_pct}], adopted_next: {fy, amount_m: Figure}|null}` FY2021–FY2026 from the CSV (no zero-fill for absent years); `adopted_next` is the next adopted year printed in the budget book but not yet in the CSV (FY2027 $62.0M, Vol. I p.89, taken from funnel bar4), drawn as a separate labelled point.
- **glossary.json** `[5 × {term, plain}]`: General Fund, one-time resources, structural deficit, reserve contribution, pension ADC.
- **series.json** `{gf_by_fy: {"2011".."2026": {revenue_m, expense_m, by_account_type: {type: m}}}, gf_dept_by_fy: {"2011".."2026": [[dept, amount_m], ...]}, vintage: {fetched_at, sha256: {name: hash}}}`. Note: FY2026 `gf_dept_by_fy` contains a blank department name `""` (19.569) — never render a blank label.
- **budget_tree.json** (`pipeline/budget_tree.py` `build_budget_tree`) — the opening section's pots bar and twin drill-down maps. `{bar_fy: 2027, detail_fy, total_m: Figure, sources: {"s0": Source, ...}, descs: {key: {text, src: str|null, link: str|null}}, unassigned: {value_m, dept_name}|null, unmatched: {rows, value_m}, pots: [Pot×5]}`.
  - `Pot = {id, label, value_m, src, answers: {what, money_from, committed_to, who_decides: each {text, src}}|null, in: Node, out: Node}`. Order and labels: `general_fund` "General Fund" 2256.7, `utilities` "Utilities" 1915.1, `purpose` "Money tied to a purpose" 1207.9, `cip` "Construction projects" 858.1, `internal` "Internal services & other" 249.2 (our arithmetic: 225.7 + 23.5). `value_m` is always the FY2027 bar value from headline.json.
  - `Node = {name, key, value_m, fy, src, children: [Node]|null, offsets: [{name, value_m}]|null}`. `src` is a key into `sources` (each distinct Source stored once, keys `s0, s1, …` in first-use order). CSV nodes cite "City of San Diego open data: operating budget CSV, FY{detail_fy} adopted" (page null). `key` looks up `descs`: the category / revenue type / department / fund / curated row name; an account uses its category's key; "Everything else" is `_everything_else`; a blank department is "Not named in the city's data" / `_unnamed`; spending with no fund is "Not assigned to a fund in the city's data" / `_no_fund` (a child of the `internal` pot's `out` root; `unassigned` gives its total and department). Map roots are named "<label> money in" / "<label> money out", key = pot id.
  - Years (ruling R4): GF and CIP roots and their top level are FY2027 (GF in root 2256.6 = Table 2 total; GF out root 2256.7 = headline; CIP roots 858.1). Everything below them, and every level of the utilities, purpose and internal maps, is `detail_fy` (the latest CSV year with GF spending; 2026 now). CSV-backed roots carry `fy = detail_fy` and their CSV net sum (FY2026: utilities 2024.9 in / 1702.3 out, purpose 942.9 / 1000.6, internal 266.8 / 341.4), not the bar value.
  - Levels: GF in = 12 Table 2 categories → accounts (matched by account type plus case-insensitive include/exclude on account name or group; FY2026 GF revenue matching no category goes under "Other Revenue", and the build stops if it reaches $5M). GF out = 9 funnel bar4 departments → plain categories → accounts ("All other" → the other CSV departments → categories; "Citywide Program Expenditures" = CSV "Citywide Expenses"; dept "Major Revenues" excluded). Utilities / purpose / internal: in = revenue type → account, out = fund → category → account. CIP: in = funding sources (incl. derived "Other sources"); out = departments → listed projects + "Other projects" (our arithmetic, dept − listed, when > 0.05; a department whose only child would be "Other projects" has `children: null`).
  - Rules: at most 10 children (9 largest + "Everything else", which nests the same way); at most 3 named levels below a root. A child with net value ≤ 0 is listed in its parent's `offsets`, not drawn; a CSV node's `value_m` is its net sum including offsets. A line with |value_m| < 0.05 is not listed by itself (R10, amended): such lines are folded into the parent's "Everything else" (and each nested one on the way down), or into a new "Everything else" leaf if there is none; if they net negative they become one "Everything else" offset; only a fold under 0.05 either way is dropped. So a CSV node's children + offsets match its value within 0.05, and no offset is ever $0.0.
  - Opening thresholds (ruling R9, for size): a fund or department opens into categories only at ≥ $15M (`FUND_DEPT_CATEGORY_MIN_M`), a category into accounts only at ≥ $50M (`ACCOUNT_LEVEL_MIN_M`), and a CSV "Everything else" box into its rolled items only at ≥ $50M (`EVERYTHING_ELSE_OPEN_MIN_M`); below that a box is a leaf. Full itemization would be ~454 KB.
  - `unmatched` counts the detail-year rows the loader drops because their account number is missing from ref_accounts.csv (FY2026: 12 rows, 83.063; drawn nowhere, stated in the methods note).
  - Checks (`checks.py`): file < 130,000 bytes; for every node whose children all share its `fy`, children + offsets equal `value_m` within 1% (children from a different year are detail and are not checked).

Popover convention: any element with `data-src-doc`, `data-src-page`, `data-src-url` gets a footnote button; figures in copy are `<span class="figure" data-src-...>`. Acceptance checks assert `.figure:not([data-src-url])` is empty and that every `[data-src-url]` has a footnote button.

Build output: `python3 -I run.py build` writes every file to a temporary directory next to `data/build/`, runs `pipeline/checks.py` there, and only then swaps it into place. On any validation or check failure `data/build/` is left as it was.

Cached source text: the citations point at public URLs (each Figure's `source.url`). A local cache of the PDFs and their `pdftotext -layout` text is optional and not part of the repository.
