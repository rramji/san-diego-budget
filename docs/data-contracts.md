# Built data contracts (data/build/*.json)

All files are compact JSON. Every hand-transcribed number is a **Figure** `{"value": number, "source": {"doc": str, "page": int|null, "url": str}}`. Money fields end in `_m` and are **millions of dollars**. Fiscal years are 4-digit ints; JSON object keys for years are strings ("2023"). The site fetches `../data/build/<name>.json` relative to `site/index.html` (serve the repo root).

- **budget_tree.json** (`pipeline/budget_tree.py` `build_budget_tree`) — the opening section's pots bar and twin drill-down maps. `{bar_fy: 2027, detail_fy, total_m: Figure, sources: {"s0": Source, ...}, descs: {key: {text, src?: str, link?: str}}, unassigned: {value_m, dept_name}|null, unmatched: {rows, value_m}, pots: [Pot×5]}`.
  - **Encoding (ruling R11): absent ≡ null.** To keep the file small, a node omits `children`, `offsets` or `src` when the value would be null, and a `descs` entry omits a null `src` (categories) or `link`. Readers must treat a missing field exactly as null (`n.children ?? null`).
  - `descs` comes from `data/curated/labels.json` (validated by `build.py` `build_labels`): categories first (shared, unsourced definitions), then nodes (cited; `src` from the registry) override on the same key. Copy may contain the placeholder `{detail_fy}`, which the builder replaces with `detail_fy` in descs and answers.
  - `Pot = {id, label, value_m, src, answers: {what, money_from, committed_to, who_decides: each {text, src}}|null, in: Node, out: Node}`. Order and labels: `general_fund` "General Fund" 2256.7, `utilities` "Utilities" 1915.1, `purpose` "Money tied to a purpose" 1207.9, `cip` "Construction projects" 858.1, `internal` "Internal services & other" 249.2 (our arithmetic: 225.7 + 23.5). `value_m` is always the FY2027 bar value from headline.json.
  - `Node = {name, key, value_m, fy, src?, children?: [Node], offsets?: [{name, value_m}]}` (absent ≡ null; `src` is present on every node today). `src` is a key into `sources` (each distinct Source stored once, keys `s0, s1, …` in first-use order). CSV nodes cite "City of San Diego open data: operating budget CSV, FY{detail_fy} adopted" (page null). `key` looks up `descs`: the category / revenue type / department / fund / curated row name; an account uses its category's key; "Everything else" is `_everything_else`; a blank department is "Not named in the city's data" / `_unnamed`; spending with no fund is "Not assigned to a fund in the city's data" / `_no_fund` (a child of the `internal` pot's `out` root; `unassigned` gives its total and department). Map roots are named "<label> money in" / "<label> money out", key = pot id.
  - Years (ruling R4): GF and CIP roots and their top level are FY2027 (GF in root 2256.6 = Table 2 total; GF out root 2256.7 = headline; CIP roots 858.1). Everything below them, and every level of the utilities, purpose and internal maps, is `detail_fy` (the latest CSV year with GF spending; 2026 now). CSV-backed roots carry `fy = detail_fy` and their CSV net sum (FY2026: utilities 2024.9 in / 1702.3 out, purpose 942.9 / 1000.6, internal 266.8 / 341.4), not the bar value.
  - Levels: GF in = 12 Table 2 categories → accounts (matched by account type plus case-insensitive include/exclude on account name or group; FY2026 GF revenue matching no category goes under "Other Revenue", and the build stops if it reaches $5M). GF out = 9 funnel bar4 departments → plain categories → accounts ("All other" → the other CSV departments → categories; "Citywide Program Expenditures" = CSV "Citywide Expenses"; dept "Major Revenues" excluded). Utilities / purpose / internal: in = revenue type → account, out = fund → category → account. CIP: in = funding sources (incl. derived "Other sources"); out = departments → listed projects + "Other projects" (our arithmetic, dept − listed, when > 0.05; a department whose only child would be "Other projects" has `children: null`).
  - Rules: at most 10 children (9 largest + "Everything else", which nests the same way); at most 3 named levels below a root. A child with net value ≤ 0 is listed in its parent's `offsets`, not drawn; a CSV node's `value_m` is its net sum including offsets. A line with |value_m| < 0.05 is not listed by itself (R10, amended): such lines are folded into the parent's "Everything else" (and each nested one on the way down), or into a new "Everything else" leaf if there is none; if they net negative they become one "Everything else" offset; only a fold under 0.05 either way is dropped. So a CSV node's children + offsets match its value within 0.05, and no offset is ever $0.0. No box opens into a copy of itself (ruling R12, a post-pass `_collapse_single` before compaction): while a node has exactly one drawn child and no offsets, that child's children and offsets move up to the node (repeated down a chain), or, if the child has none, the node becomes a leaf. The node keeps its own name, value, year and source, so the sum check is unaffected (e.g. GF in Sales Tax and Transient Occupancy Tax are FY2027 leaves; "Not assigned to a fund…" lists its accounts directly). A node with one child plus offsets keeps that child. FY2026: 12 such nodes before the pass, 0 after.
  - Opening thresholds (ruling R9, for size): a fund or department opens into categories only at ≥ $15M (`FUND_DEPT_CATEGORY_MIN_M`), a category into accounts only at ≥ $50M (`ACCOUNT_LEVEL_MIN_M`), and a CSV "Everything else" box into its rolled items only at ≥ $50M (`EVERYTHING_ELSE_OPEN_MIN_M`); below that a box is a leaf. Full itemization would be ~454 KB.
  - `unmatched` counts the detail-year rows the loader drops because their account number is missing from ref_accounts.csv (FY2026: 12 rows, 83.063; drawn nowhere, stated in the methods note). The methods note (`site/methods.js`, section 1's Dig deeper) reads `bar_fy`, `detail_fy`, `unassigned`, `unmatched` and the `_no_fund` node from this file; it states the opening thresholds and category count from its own `RULES`, which `tests/test_build.py` checks against `budget_tree.py` and `categories.py`.
  - Checks (`checks.py`): file < 130,000 bytes (127,713 after R12); every level-1 child of `general_fund` in/out, `utilities` out and `purpose` out, plus `_no_fund`, has a `descs` entry with text; for every node whose children all share its `fy`, children + offsets equal `value_m` within 1% (children from a different year are detail and are not checked).

Popover convention: any element with `data-src-doc`, `data-src-page`, `data-src-url` gets a footnote button; figures in copy are `<span class="figure" data-src-...>`. Acceptance checks assert `.figure:not([data-src-url])` is empty and that every `[data-src-url]` has a footnote button.

Build output: `python3 -I run.py build` writes every file to a temporary directory next to `data/build/`, runs `pipeline/checks.py` there, and only then swaps it into place. On any validation or check failure `data/build/` is left as it was.

Cached source text: the citations point at public URLs (each Figure's `source.url`). A local cache of the PDFs and their `pdftotext -layout` text is optional and not part of the repository.
